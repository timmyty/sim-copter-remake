The reported screenshot was taken from the installed v1.0.12 executable, dated 01:41 on October 14. The user clarified that camera jitter occurs **inside a helicopter after taking control**. A new physics-backed regression reproduces continual vertical motion beside a static obstacle (15 cm range after twelve seconds of settling). The avoidance probe used the previous frame's avoided ground lift, creating feedback between its pitch search and ground-height response. It now searches using the baseline view's required lift, independent of the prior response. Ordinary smoothing remains; startup resets immediately solve obstruction response before revealing the camera. Twelve obstacle placements test both settled motion and the first second after reset.

The city tour pauses ordinary city ticks while moving a separate camera. Smoke and beacons had retained camera-facing geometry from an earlier view; the reproduction test turned the tour away from a plume and found the old cards still present. `RefreshCameraFacingEffects` is shared by normal city ticks and the tour, after updating the camera manager, including the return to the controlled pawn. It only updates presentation, not mission time. Canyon's existing offscreen tour test now includes these effects, using a matching player camera rather than silently omitting them.

The same investigation reproduced a second effect fault: converting a depth of 205,000 cm or more into signed 16.16 could overflow, then clamp to zero and produce a full-size effect instead of culling it. The rasterizer now rejects out-of-range/non-finite depths before conversion, preserving original near-range arithmetic.

The first offscreen Canyon capture exposed another actual effect fault: `SyncLightsFromPlayerCamera` clamped a missing viewport's width to **one pixel**, expanding the one-pixel beacon minimum into enormous white/blue cards across the view. A loading/minimized viewport now retains the last valid width (or the original 560-pixel default). The size utility returns no pixel floor for an invalid width, and changes to width/FOV invalidate cached geometry even if the camera and blink phase are unchanged. The test measures actual beacon mesh bounds and an FOV-only change; Canyon's descent capture now rejects a mostly pale sheet. The original bad render is preserved under `before-viewport-fix`. A passing lit-pixel count alone was insufficient evidence; inspect the images.

Both paths now preserve it, covering mission, parked-aircraft, hangar and service labels. The Slate regression uses a real parked-helicopter waypoint and checks creation during the hidden state, repeated refreshes, and restoration after the tour.
